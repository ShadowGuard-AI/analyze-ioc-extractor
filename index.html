Panel one: the work of the office, it extracts

analyze-ioc-extractor extracts Indicators of Compromise such as IP addresses, URLs, and email addresses from a text file or standard input, using regular expressions.

The word extracts holds the heading position because this tool pulls its finds out of text put in front of it. Nothing is fetched, queried, or looked up anywhere else.

Panel two: reporting for the crossing

git clone https://github.com/ShadowGuard-AI/analyze-ioc-extractor
cd analyze-ioc-extractor
pip install -r requirements.txt

python3 main.py [INPUT] [-o OUTPUT] [-i IOC_TYPE] [-v] [-q]

INPUT is explained exactly as the source explains it: an input file, or a dash for standard input, with standard input as the default.

Panel three: the punch shapes, one stub per control

-h shows the help message and exits.

-o, also written --output, names an output file in CSV format.

-i, also written --ioc-type, chooses the kind of IOC to extract: ip, url, email, md5, sha1, sha256, domain, or all, with all as the default.

-v, also written --verbose, enables verbose output, described in the source as logging.

-q, also written --quiet, suppresses all output except errors.

Each stub is punched with its own shape, and no stub borrows another stub's wording.

Panel four: the stub book, verified behaviour entered by hand

A sample containing an IP address, a URL, an email address, an MD5 hash, and a domain produced rows for each of those types. With -i ip, only the IP row was produced. With -o, the CSV carries two columns, ioc_type and ioc_value. Reading from standard input with a dash works. A missing input file exits with code 1.

Caution, given its full weight: the URL pattern also matches bare domains and bare IP addresses, so a url row is a pattern match, not a validated URL.
